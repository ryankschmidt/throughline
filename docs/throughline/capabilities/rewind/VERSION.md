# ThroughLine rewind capability v1.3.0

**Current version: 1.3.0 (2026-10-10) — versioned 0.0.60 rewind carry.**

Version 1.3.0 records the ten protected-path changes carried between 0.0.56 and the 0.0.60 preserve-base release, which shipped under a single-use version exception; upstream reconciliation must preserve the existing same-session rewind behavior and all pinned regression cases.

**Previous version: 1.2.0 (2026-10-02) — rewind keeps the same Claude session, like the CLI.**

Rewind no longer forks the Claude transcript. It resumes the same native session cut before the chosen message, so every message id stays the same and rewinds repeat as many times as the operator wants. A rewind to the first message keeps the session too.

- The Claude adapter resumes the same session with resumeSessionAt set to the entry before the chosen message, instead of forkSession plus boundary remapping. The fork-ancestry repair from 1.1.0 is not carried; its identity module and nine cases leave the manifest.
- A first-message rewind cuts at the session-start entry the prompt hangs from, read from the native transcript by the owned helper apps/server/src/throughline/rewind/claudeTranscriptParent.ts. With nothing before it, the rewind refuses and changes nothing.
- The cut stays in the resume cursor until the next reply, so a restart before the next prompt cannot undo the rewind.
- Five new pinned adapter cases; two fork-only cases removed. Probes against Claude Code 2.1.286 confirmed same session id across three repeated rewinds and a first-message rewind.
